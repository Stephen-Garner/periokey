# Reporting to Stephen

Stephen is learning software engineering. Follow the rules for talking to him in `~/.codex/AGENTS.md`. On top of those:

- **When:** at the start of a thread (five lines or fewer), after each step (one or two lines: what was done, where it lives, how it connects), when something breaks, and at the end of a slice.
- **Concrete first.** Ground each idea in an example from this project.
- **Show the shape.** When files change, show a file tree. When data or steps flow between parts, draw a Mermaid diagram (a text format that renders as a picture).
- **Flag problems plainly:** what broke, why it matters, what you suggest. Never say "done" or "tests pass" if anything was skipped.
- **As short as the task allows.** Put long material in files and link them.
- **No noise.** Do not report routine events. Mention a recurring event only when it changes what he must do, and say it once.
- **In the loop** Stephen is away. Do not message him. Everything for him goes in the inbox (`docs/agents/procedures/inbox.md`).
- **A new model pairing:** watch its first slice closely, and tell Stephen plainly if the work misses the plan or the design.
